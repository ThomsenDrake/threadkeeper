# Direct learned-provider lifecycle acceptance

The native harness verifies canonical extraction and vector content against direct provider responses, independently checks correction identity/times, and runs from an archived source with private frozen dependencies. One fresh run passed on immutable `28a83b8`; the earlier native failure and bounded nullable-usage diagnostic remain recorded below. [PR #15](https://github.com/ThomsenDrake/threadkeeper/pull/15) records current review/merge status; final-head review is required before a guarded merge. Earlier artifacts retain their own source identities and narrower assertions.

`pnpm integration:learned /tmp/threadkeeper-learned-evidence.json` builds and removes a disposable native stack. Run from a clean committed implementation with Node 24, pnpm 11.25.0, a local Docker daemon, permitted Nebius egress and an operator-managed `NEBIUS_API_KEY` binding. Prepare the project normally with `corepack pnpm@11.25.0 install --frozen-lockfile`; the launcher resolves that project's configured pnpm store and creates a private offline copy with the archived lockfile, integrity verification and lifecycle scripts disabled. A populated project cache is required; an existing `node_modules` alone does not establish cache readiness. An explicit output path argument is required, and the destination must not already exist. This explicitly performs billed inference within the existing authorized provider account; do not run it as part of the credential-free baseline.

The runner creates a unique Compose project and generated local owner/database credentials. Only the API binds a random localhost port. PostgreSQL/pgvector, the production application image, the actual API and background worker use synthetic context. The application calls `https://api.tokenfactory.nebius.com/v1/` directly with `nvidia/Nemotron-3_5-Lightning`, measured opt-in reasoning effort `none`, and `Qwen/Qwen3-Embedding-8B` at 256 dimensions. It does not route inference through a fixture, relay or Executor.

Two independently authenticated MCP SDK clients exercise source-only capture, duplicate receipt identity, observable extraction completion, original source evidence and learned paraphrase recall. The owner then corrects the deadline, rejects a stale revision and forgets the preference using a fresh deletion preview. Correction independently preserves the original creation/effective times, advances the original update time and retains the portable `correction:<memory-id>:<revision>` evidence identity; correction source and revision timestamps must match the authoritative transaction. Both clients recall the authoritative current deadline. The runner checks deleted sources through HTTP/MCP, rejects replay under both the original source identity and normalized content, and verifies export tombstones, source checksums, native vectors and extraction-job cleanup. Negative recaptures explicitly disable extraction, so they cannot spend on inference if a deletion fence regresses.

An opt-in observer wraps each process's original `fetch` without changing its destination. It captures request/response hashes, safe model identities, timing, response status and token usage, including replies later rejected by application validation. It records no keys, headers, prompts or raw responses. Fixed per-process budgets allow at most two extraction requests, four worker embedding requests and eight API query embedding requests; the normal lifecycle needs fewer. Provider usage must be reported for every sent request and reported totals must agree with available components. Invalid primary counts and negative, fractional or unsafe detail counts fail validation before sanitization can hide them. Optional null detail counts remain unknown rather than becoming zero. Recognized detail counts must not exceed their available prompt/completion parent counts. The native overlay explicitly enables bounded input/vector fingerprints; only SHA-256 hashes of exact inputs and normalized float32 components are retained. Both initial deadline/preference SQL vector snapshots and the corrected deadline snapshot must match their own observed worker responses. A separate canonical fingerprint binds the parsed Nemotron response memories to the persisted extracted records. These hashes establish normalized content equality for the observed records; they do not prove an arbitrary causal path through the adapter. Observation adds no provider calls and accepts equal actual vectors when the provider returns them.

A built-in-only launcher archives one Git commit and completes the private frozen dependency installation before a separate process imports its private TypeScript loader, operational runner, scenarios, assertions or accounting helpers. It clears external Node loader settings and records the lockfile hash, pinned package manager and loader version. Docker builds that same source archive; host validation does not link the mutable invocation checkout's dependencies. Evidence is reserved after source capture and before Docker/provider work, including for a fresh repository-local destination. The result records the commit, tree and implementation hashes, native database versions, actual API/worker/PostgreSQL container image IDs, optional repository digests and sanitized provider attempts. The archived build IID must equal both actual application container image IDs. A successful artifact is written only after containers, network, volume, application image and generated credential files are removed; publication truncates the reserved descriptor and verifies its exact bytes and path identity. Failures print sanitized attempt evidence and exit nonzero. SIGINT/SIGTERM stop the active subprocess even during cleanup. Successive cleanup subprocesses inherit the existing stop request, keeping each command's termination bounded while independent teardown steps continue. The runner never edits reusable environment settings, deploys, changes DNS or provisions paid resources.

A passing run establishes only the assertions exercised by that recorded harness version in one bounded synthetic lifecycle against hosted learned providers. It does not establish installed-host autonomous tool selection, local GPU parity, broad semantic accuracy, archive-scale performance, provider-retained deletion, deployment or release readiness.
