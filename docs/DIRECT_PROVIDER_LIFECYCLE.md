# Direct learned-provider lifecycle acceptance

`pnpm integration:learned /tmp/threadkeeper-learned-evidence.json` builds and removes a disposable native stack. Run from a clean committed implementation with Node 24, pnpm 11.25.0, a local Docker daemon, permitted Nebius egress and an operator-managed `NEBIUS_API_KEY` binding. The output path must not already exist. This explicitly performs billed inference within the existing authorized provider account; do not run it as part of the credential-free baseline.

The runner creates a unique Compose project and generated local owner/database credentials. Only the API binds a random localhost port. PostgreSQL/pgvector, the production application image, the actual API and background worker use synthetic context. The application calls `https://api.tokenfactory.nebius.com/v1/` directly with `nvidia/Nemotron-3_5-Lightning`, measured opt-in reasoning effort `none`, and `Qwen/Qwen3-Embedding-8B` at 256 dimensions. It does not route inference through a fixture, relay or Executor.

Two independently authenticated MCP SDK clients exercise source-only capture, duplicate receipt identity, observable extraction completion, original source evidence and learned paraphrase recall. The owner then corrects the deadline, rejects a stale revision and forgets the preference using a fresh deletion preview. Both clients recall the authoritative current deadline. The runner checks deleted sources through HTTP/MCP and verifies export, native vector and extraction-job cleanup.

An opt-in observer wraps each process's original `fetch` without changing its destination. It captures request/response hashes, safe model identities, timing, response status and token usage, including replies later rejected by application validation. It records no keys, headers, prompts or raw responses. Fixed per-process budgets allow at most two extraction requests, four worker embedding requests and eight API query embedding requests; the normal lifecycle needs fewer. Provider usage must be reported for every sent request before the run can pass.

The result records the source commit, tree and hashes of tracked implementation/configuration files, native database versions, application image identity and sanitized provider attempts. A successful artifact is written only after containers, network, volume, application image and generated credential files are removed. Failures print sanitized attempt evidence and exit nonzero. SIGINT/SIGTERM trigger cleanup. The runner never edits reusable environment settings, deploys, changes DNS or provisions paid resources.

This establishes one bounded synthetic lifecycle against hosted learned providers. It does not establish installed-host autonomous tool selection, local GPU parity, broad semantic accuracy, archive-scale performance, provider-retained deletion, deployment or release readiness.
