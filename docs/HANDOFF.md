[PR #20](https://github.com/ThomsenDrake/threadkeeper/pull/20), `codex/owner-kind-correction`, was developed as an independent increment based on main **`ede71ba15ea5d96e390a86b720b8d36e0ca267f4`**. Those learned measurements remain separate from the owner-control validation.

Owners can change a saved memory's **kind** in the existing correction form, or change a candidate's kind while explicitly confirming it. The selector begins at the current kind. Omitted kind preserves it; ordinary confirmation and dismissal preserve it, and dismissal rejects edits. A stale correction reloads the current classification before another save. Every revision now records its kind, so the profile and export retain the original model classification, statement, evidence and provider alongside the separate owner-authored revision. Same-text reclassification keeps the memory identity and original creation time; revision increments retain authorization, vector/attempt invalidation, held-response fences and kind-independent forgetting protections. This provides manual repair for classification errors; it does not improve extraction quality or prevent extra dialogue/quoted records from being admitted.

The new checksum-tracked **008** migration backfills historical kinds from the current memory, which earlier application versions kept immutable. It preserves already-recorded revision kinds on rerun. Exports now use strict **`threadkeeper.export.v2`** with required per-revision kinds. Strict legacy **v1** import remains supported by explicitly normalizing its constant kind before ordinary history/conflict checks. V2 cannot omit historical kinds, and a legacy reimport cannot overwrite an already corrected kind timeline. Import reconstructs the original admission identity from revision 1's kind. Older binaries cannot write the upgraded revision schema or consume v2; upgrade destinations before import. See [portability and operator procedure](PORTABILITY.md).
